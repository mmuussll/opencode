يتكامل OpenCode مباشرة مع منصة GitHub لأتمتة مراجعة الكود، وحل المشكلات (*Issues*)، وتجهيز طلبات السحب (*Pull Requests*) عبر سير عمل GitHub Actions.

---

## كيف يعمل التكامل؟

عند إعداد OpenCode في مستودعك، يمكنك:
1. **المراجعة الآلية للـ PRs:** فحص طلبات السحب فور فتحها وتنبيه المطورين لأي مشاكل برمجية أو أمنية.
2. **التنفيذ عبر التعليقات:** مناداة OpenCode داخل أي طلب سحب أو مشكلة عبر كتابة `/opencode` أو `/oc` متبوعة بالأمر المطلوب، وسيقوم الوكيل بتنفيذه ورفع التعديلات في فرع جديد تلقائياً.

---

## إعداد سير عمل GitHub Actions

أنشئ ملفاً في مسار مشروعك: `.github/workflows/opencode.yml`:

```yaml
name: opencode-workflow
on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]
  issue_comment:
    types: [created]

jobs:
  opencode:
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Run OpenCode Action
        uses: anomalyco/opencode/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          model: anthropic/claude-3-5-sonnet-20241022
          use_github_token: true
```

## أمثلة استخدام الأوامر في تعليقات GitHub

### 1. إصلاح خطأ برمجي من خلال مناقشة الـ PR
اكتب في تعليق داخل طلب السحب:
```text
/oc راجع رسالة الخطأ في الاختبار الأخير وقم بتحديث منطق التحقق في auth.ts
```

### 2. تنفيذ مهمة من داخل Issue
في أي تذكرة أو مشكلة في المستودع:
```text
/opencode نفذ الوظيفة الموضحة في وصف التذكرة وافتح Pull Request جديد بالتعديلات
```

---

## الأمان وحماية الأسرار

* لا تقم بتضمين مفاتيح الـ API كنصوص واضحة في ملفات YAML أبداً.
* استخدم دائماً **GitHub Repository Secrets** لتخزين المفاتيح مثل `ANTHROPIC_API_KEY` أو `OPENAI_API_KEY`.
