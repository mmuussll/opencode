يعتمد OpenCode على بنية وكلاء ذكية تتيح فصل المهام وفق مستويات الأمان والغرض المطلوب، مما يضمن أداء المهام البرمجية بكفاءة وتجنب التعديلات غير المقصودة.

---

## الأنماط الأساسية للوكلاء

### 1. وكيل البناء (`build`)
* **النمط الافتراضي للتطوير:** مصمم لكتابة الأكواد، وإصلاح الأخطاء، وإضافة الميزات الجديدة.
* **الصلاحيات:** يملك صلاحيات كاملة لقراءة الملفات، تعديل وحفظ الملفات، وتنفيذ الأوامر في الطرفية (مثل تشغيل الاختبارات أو بناء المشروع).
* **متى يُستخدم؟** عند الرغبة في إنجاز تعديلات برمجية مباشرة على الكود.

### 2. وكيل التخطيط (`plan`)
* **نمط آمن للقراءة فقط (Read-Only):** لا يملك صلاحية تعديل أي ملف في مشروعك أو تنفيذ أوامر قد تُحدث تغييرات على النظام.
* **القدرات:** تحليل الكود، رسم المخططات المعمارية، تقديم تقارير عن المشكلات، وكتابة خطط عمل تفصيلية خطوة بخطوة.
* **متى يُستخدم؟** عند بدء ميزة جديدة معقدة، أو دراسة مشروع غير مألوف، أو قبل السماح لوكيل البناء بإجراء تعديلات جذرية.

> [!TIP]
> يمكنك التبديل الفوري بين وكيلي `build` و `plan` في أي وقت بالضغط على مفتاح `Tab`.

---

## الوكلاء الفرعيون (Subagents)

عند مواجهة مهمة فرعية تتطلب تركيزاً منفصلاً دون تلويث سياق المحادثة الرئيسي، يمكن لـ OpenCode استدعاء وكيل فرعي (Subagent) للقيام بالمهمة وإرجاع النتيجة الملخصة إلى الوكيل الرئيسي.

### أمثلة على الوكلاء الفرعيين:
* **وكيل البحث والتوثيق (Research Agent):** يبحث في ملفات المشروع أو المستندات الخارجية ويستخرج الإجابات المحددة.
* **وكيل الاختبار والتشخيص (Testing Agent):** يقوم بتشغيل مجموعات الاختبارات وتحليل سجلات الأخطاء.

---

## تخصيص وتعيين النماذج لكل وكيل

يمكنك تعيين نموذج ذكاء اصطناعي مختلف لكل وكيل حسب طبيعة المهمة في ملف إعدادات `opencode.json`:

```json
{
  "agents": {
    "build": {
      "model": "anthropic/claude-3-5-sonnet-20241022",
      "temperature": 0.2
    },
    "plan": {
      "model": "deepseek/deepseek-chat",
      "temperature": 0.5
    }
  }
}
```
